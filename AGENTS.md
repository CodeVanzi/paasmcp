# AGENTS.md — AI Agent Instructions for PaaSMCP

## Project Overview
**PaaSMCP** is an Agent-First & Security-First Micro-PaaS & Model Context Protocol (MCP) Server written in TypeScript (Node.js ESM).

## Codebase Structure
- `src/guard.ts`: Risk policy (free / confirm / strong / forbidden), approval requests for agents, audit log.
- `src/config.ts`: State management (atomic writes + `withStateLock` across MCP, CLI and dashboard) (`/opt/homelab/paasmcp/state.json`), port allocator (`4000-4998`, `4099` for dashboard), slug sanitization, and strict security validators (`validateEnvKey`, `validateBranchName`, `validateResourceLimit`).
- `src/vault.ts`: AES-256-GCM encryption/decryption for per-app and `system` JSON secrets, binary AES-256-GCM (`PMCP` wire format) for database backups & sync bundles, constant-time `timingSafeCompare`, and `parseDotenv` (pasted `.env` files from the dashboard; skipped lines are reported by number only).
- `src/database.ts`: Shared PostgreSQL 16 and Redis 7 cluster provisioning, isolated SQL user/database creation, Vault secret injection, and encrypted `pg_dump` / Redis backup & zero-plaintext-disk restore (`paas_db_backup`).
- `src/mirror.ts`: two-server mirror. `offerMirror` (replication role, slot, pg_hba for the peer, Tailscale bind, backups bucket, token encrypted with the federation cluster key), `acceptMirror` (pg_basebackup + read-only streaming container `paasmcp-mirror-<peer>`), `mirrorStatus`, `promoteMirror` (guard `mirror.promote`, strong; epoch++, DATABASE_URL to the copy, redeploy, re-expose; refuses a superseded copy without `stale`). Several copies of one server (star): `watchTick` marks a copy `supersededBy` when the arbiter names another owner (or `retireCopy`, guard `mirror.retire`), and only claims with a copy seen streaming in the last 15 minutes (`streamedAt`). Origin gone for good: `offerMirror --from-copy-of <origin>` to a third server puts `dataOf` in the token; the copy keeps the origin's node id with `servedByNodeId` (whose liveness counts), and a server that lost a takeover stops those apps (`lost:` in `watchTick`, deploys refused).
- `src/active.ts`: active-active. `activeReadiness`, `setActiveActive` / `switchActiveActive` (guard `app.active`, confirm), `publishActiveState` (encrypted manifest in `paasmcp_meta.active_manifest` on the origin's Postgres), `syncActivePeers` (peer side, reads the live copy, validates every field, deploys the exact commit), `activeComposeExtras` (extra_hosts to the origin, Tailscale port, `DATABASE_REPLICA_URL`).
- `src/filesync.ts`: bucket copy between two Garage nodes with the app's own key (SigV4, no admin token crosses servers). `planFileSync` (pure: `mirror` deletes extras, `additive` for handback), `syncBucket` (refuses to empty a copy from an empty source). Called by `syncActiveFiles` in `active.ts` (via `ensureBucketWithImportedKey` in `storage.ts`; `mirror watch` runs it in the background, outside the state lock, so it never delays a failover check) and by `handbackMirror`.
- `src/activetunnel.ts`: Cloudflare Tunnel just for apps on both servers. `enableActiveTunnel` / `disableActiveTunnel` (guard `active.tunnel` confirm), `routeActiveTunnel` (ingress first, then DNS, each hostname once the peer's copy answers; no API call when unchanged), `ensureConnector` / `applyPeerTunnel` (pinned cloudflared, token in a 0600 `.env`, peer gets it in the manifest), `tunnelWatchTick` (health watch in `mirror watch`: a sick copy stops its connector). Never run the main tunnel's token on a second server.
- `src/edge.ts`: self-hosted entry. Pinned Caddy on the host network (`installEdge`, guard `edge.install` strong), `addEdgeSite` (guard `app.expose` public), `buildCaddyfile` (round robin + health checks on both servers' copies), `edgeStatus` (probes each backend).
- `src/arbiter.ts`: arbiter server/client for automatic failover (`arbiterDecide` is the pure rule set: claim only when the owner looks dead to the arbiter too, epochs only go up, only the owner hands back). Key derived from the cluster key. One arbiter can serve several clusters: one key each, state kept per cluster id (`X-Paasmcp-Cluster`), keys managed with `arbiter add-key|remove-key|clusters`. Signed replies carry `about` (host, version); `arbiterInstallCommand`/`publicRepoUrl` build the dashboard's ready-to-paste install command (no credentials in the repo URL). `mirror watch` records its last arbiter contact in `<data>/mirror-watch.json` (`readWatchContact`). Pairing by code: `openArbiterPairing` / `handlePairRequest` (arbiter side, `/pair`) and `pairWithArbiter` (server side); `serveArbiter` re-reads the key file.
- `src/judge.ts`: a PC with PaaSMCP as arbiter: `ensureLocalJudge` (container `paasmcp-arbiter` from a copy of `JUDGE_FILES`), `beJudge`, `localJudgeStatus`, `stopLocalJudge` (guard `judge.stop`), and `listTailscalePeers` / `findJudgeCandidates` (Tailscale devices, every device kept; reuse them for other discovery).
- `src/pcinstall.ts`: Connections → PCs. `listTailnetPcs` (every Tailscale device: runs PaaSMCP / no PaaSMCP / off / not possible here), `knownPaasmcpIps`, `sshBanner` (first line of port 22: Tailscale SSH or OpenSSH). Read-only.
- `src/poller.ts`: polling auto-deploy (`autoDeploy: "poll"`, `git ls-remote` vs `lastCommit`). Who checks (`ensurePollSchedule`, no sudo): the dashboard when it runs (`src/pollloop.ts` starts `paasmcp poll run` every 2 min inside the dashboard container), else a systemd timer (system-wide as root, the user's own timer otherwise).
- `src/selfupdate.ts`: the dashboard follows a branch (opt-in, guard `dashboard.follow` confirm; `paasmcp dashboard follow` or the button on its row). Never runs from the folder being edited: each new commit is cloned into `paasmcp/control-plane/releases/<sha>`, `npm ci` + build + tests inside the dashboard image (`buildInImage`), then swapped in (`swapTo`: compose up, 60 s check, back to the previous code on failure); a failed commit is not retried. Inside the dashboard container the swap runs in a short-lived helper container (`startSwapHelper`, `dashboard swap <sha> --run <id>`). Progress goes to the same deploy record as apps (`continueDeployRun`). The dashboard record never gets a `repoUrl` (webhooks, mirrors and polling would redeploy it as an app); `deploySummary` shows the followed repository instead. Dockerfile generation is covered per language by `test/fixtures` (unit test) and `scripts/dockerfile-lab.sh` (real build + run).
- `src/updater.ts`: pinned images (`PINNED`, `imageFor` keeps an old install's image until updated), `checkUpdates` (Docker Hub tags, same major), `applyUpdate` (backup, mirror copies first, 60 s health check, rollback). Guard `update.apply` is confirm.
- `src/connections.ts`: dashboard Connections screen. `discoverCloudflare` (lists accounts, active zones and tunnels a pasted or saved token sees; changes nothing), `saveCloudflare` (checks the choice against that list, creates or reuses `paasmcp-<host>` with `config_src: cloudflare`, runs the pinned `paasmcp-tunnel` connector, guard `connect.cloudflare` when replacing a working domain/tunnel), `checkGitHub` (GET /user, saves `GITHUB_TOKEN`), `listGitHubRepos` (repository list for the Publish screen), `connectionsSummary` (never returns tokens). `ConnectionError` carries Portuguese text. API base overridable with `PAASMCP_CF_API_URL` / `PAASMCP_GITHUB_API_URL` for tests.
- `src/email.ts`: relay settings in the `system` vault, per-app SMTP/EMAIL variables (`paas_email_provision`), minimal SMTP client for `email test` (STARTTLS or 465; refuses AUTH without TLS).
- `src/storage.ts`: Garage (pinned image, admin API on loopback only), single-zone layout on first start, one bucket + key per app (`paas_storage_provision`), `S3_*` / `AWS_*` injected into the app vault.
- `src/offsite.ts`: where off-site backups go, per provider (`buildOffsiteTarget` is pure; `saveOffsiteTarget` tests with a real write/read/delete before saving to the `system` vault, guard `backup.target` when replacing), access codes (`paasmcp-backup:1:`), and revocable grants for other computers into this server's Garage (`createBackupGrant` guard `backup.grant`, `revokeBackupGrant`, `state.backupShare`). `OffsiteError` carries a Portuguese message for the dashboard. Never expose grants or the target's secret through MCP.
- `src/backup.ts`: Docker volume backups, restore test (temporary database), native S3 SigV4 off-site sync/fetch (`BACKUP_S3_*` in the `system` vault), pruning that only removes local copies already off-site, nightly run and systemd timer. `src/nightly.ts`: the dashboard container starts `backup nightly --if-due` once a day from 3:30; every nightly run writes `backups-nightly.json` first (date, result), so the dashboard and a systemd timer never both run the same day; errors send a notice (`sendNotice`).
- `src/github.ts`: a saved `GITHUB_TOKEN` is sent to github.com only as an `http.extraheader` through `GIT_CONFIG_*` environment variables (`gitEnv`), never in the clone URL, the command line or `.git/config` (an update rewrites `origin` to clean old clones). SSH Ed25519 deploy key generation + SHA256 fingerprint, GitHub API deploy key registration, git clone/pull, Zero-Config Dockerfile generator, and multi-service `docker-compose.yml` detector.
- `src/deployer.ts`: Docker Compose generation, untrusted `docker-compose.yml` security sanitization (`generateSanitizedComposeFromRepo`), CPU/RAM resource limits, blue/green cutover (`deployApp` is async: candidate container on a free loopback port, `waitForHealthy`, `HealthcheckFailedError` with the candidate's logs, `probeUrl`: inside the dashboard container 127.0.0.1 is the dashboard itself, so probes go to the container's IP on the Docker network; any new health probe of an app must use it, network alias during the swap), `:previous` image tagging for 1-second rollback, live `docker stats` metrics (`getContainerMetrics`), and `paas_doctor` diagnostics (`runPaaSDoctor`; each finding also carries a `code` + `vars` that the dashboard turns into `doc_<code>`/`docr_<code>` texts in the screen's language, so a new finding needs a code and its texts in both languages, test 46).
- `src/templates.ts`: ready-made apps (`TEMPLATES`: exact multi-arch image tag, port, data path, `firstVisitAdmin`). `prepareTemplate` writes `data/templates/<id>/docker-compose.yml`; the dashboard (`/api/templates`, `/api/templates/deploy`) publishes that folder with `deployApp` and refuses a name already used by another source. Bump a tag only to one at least two weeks old and check it runs (healthcheck) with real Docker.
- `src/appwatch.ts`: inside the dashboard container, `docker ps` every minute; `watchRound` (pure) reports an app down after `DOWN_ROUNDS` misses in a row, skips apps mid-deploy, stopped, trashed, fenced or superseded, and reports it back once it runs again. Notices go through `sendNotice`.
- `src/notify.ts`: notices (ntfy, Discord, Slack by host) for finished deploys, sent from `deploys.ts` (`notifyDeploy`, never throws): failures unless the trigger is `dashboard`, successes only for automatic triggers and when `NOTIFY_ON_SUCCESS`. `saveNotify` posts a test before saving `NOTIFY_URL` to the `system` vault; `notifySummary` never returns the URL. `NotifyError` carries Portuguese text.
- `src/trashclean.ts`: the nightly backup (`runNightlyBackup`) empties the trash: `trashPlan` (pure) warns at 27 days (`trashWarnedAt`, one notice) and deletes after 30 days and at least `WARN_DAYS` after the notice, so nothing is deleted without one; restore/destroy clear the mark; `PAASMCP_TRASH_AUTO=0` turns it off; test 54.
- `src/deployhelp.ts`: `explainDeployError` sorts a failed deploy into a kind (healthcheck, access, branch, stack, memory, build, network, trash, other) and where to fix it; the dashboard's `/api/deploy` and `/api/apps/redeploy` answer 422 with `{ error, failure }` and show it in plain words with the raw error under "details". Add a kind with its `df_*`/`dfh_*` texts in both languages (test 46).
- `src/deploys.ts`: live deploy status. `startDeployRun` (called by `deployApp`; phases detected/fetching/building/checking/switching/live/failed in `deploys/<app>.json`, last 10, pid for interrupted runs), `redactCredentials` / `cleanText` for anything stored, `githubSource` / `commitUrl` (links only from parsed owner/repo + full SHA), `deploySummary` (dashboard `/api/deploys`, `paas_status`, `paasmcp deploys`). Pass `trigger` (and `announcedCommit` when known) on every new `deployApp` call.
- `src/federation.ts`: GitHub Push Webhook HMAC-SHA256 verification (`verifyGitHubWebhookSignature`, `handleGitHubPushWebhook`) and Multi-Server HA Handshake & Encrypted State/Vault Synchronization (`paasmcp-join://` tokens).
- `src/exposure.ts`: Cloudflare Tunnel ingress API, Cloudflare DNS CNAME management, Cloudflare Zero Trust Access policy creation, and Tailscale Serve integration (from the dashboard container, `tailscale` talks to the server's tailscaled through `/var/run/tailscale`, mounted when it exists: `tailscaleSocketDir()` in config.ts; `tailscaleServeError` turns a missing CLI/socket into `ExposeError` with Portuguese text; `removeAppAddress` takes one saved address off the air: tunnel route, only a CNAME that points to a `cfargotunnel.com` tunnel, only Access apps named `PaaSMCP…`, or `tailscale serve --https=<port> off`; guard action `app.unexpose`, dashboard `/api/unexpose`, test 53).
- Code that runs in the dashboard container (`PAASMCP_IN_DASHBOARD=1`): 127.0.0.1 is the dashboard itself and host CLIs (systemctl, tailscale without its socket) are absent. Reach other containers by name or IP on the Docker network (`probeUrl`, `garageAdminUrl`).
- `src/scale.ts`: automatic scaling, measuring and deciding (phases 1 and 4). `scaleTick` (systemd oneshot timer `paasmcp scale tick`, measures without the state lock, own lock file naming its process) reads `docker stats` + times the health path + the pool balancer's visit counters; `scale/<app>.json` keeps 10 min of samples and the decision state, `scale/<app>.history.ndjson` one point per minute for 24 h. `observe` is the pure decision rule (pressure = max of CPU per copy / `targetCpu` and visits per copy / `targetRps`; `upRounds` in a row, `downAfterSeconds` below half, `cooldownSeconds`, gaps reset streaks); `rehearse` wraps it for apps without automatic scaling, `commitStep` / `holdStep` record a real step or a held one (retry backoff). Steps for apps with automatic scaling on go through `AutoHooks` (autoscale.ts); `scale/<app>.step.json` marks a step in progress (`interruptedSteps` → repair). The decision diary (`scale/diary.ndjson`) stores codes + numbers; `renderDiary` turns them into pt/en sentences. `forgetScaleData` on purge.
- `src/autoscale.ts`: scale phase 4. `parseCaddyMetrics` / `readBalancer` (balancer metrics on its admin unix socket), `applyStep` (under the state lock with a 2 s wait, re-checks the app, writes the step file, `setCopies(fromDecider)` or `reconcilePool` for a repair), `postgresConnections` (no step up at 80% of Postgres connections), `setAutoScale` (guard `scale.auto`, the caller checks it; `autoRiskParams`). Raising `max` while it is on goes through guard `scale.rule` (`ruleRiskParams` in scale.ts).
- `src/loadtest.ts`: capacity test (`paasmcp scale test`, guard `scale.test` confirm): GET only, only the app's 127.0.0.1 port, at most 64 parallel requests and 30 s per step; `classifyBottleneck` (app CPU, database, client, errors, latency).
- `src/pool.ts`: scale phase 3, helper pool on the owner's own PCs, manual copies. Origin side: `createInvite` (guard `pool.invite`; proof key = HMAC of the system vault's `POOL_INVITE_KEY`, never in state.json), `addHelper` (nonce + HMAC proof, `timingSafeCompare`, host key pinned in `pool/known_hosts`), `sshOrder` (pool key `pool/pool_ed25519`, `StrictHostKeyChecking=yes`), `poolReadiness`, `reconcilePool` (drain, rolling replace, placement), `setCopies` (guard `app.pool`; refused while automatic scaling is on unless `fromDecider`), `disablePool` (stop everything: clears automatic scaling first), `poolAfterLifecycle`, the Caddy balancer `paasmcp-pool-lb` (one named server with metrics per app, `balancerServerName`) and the tunnel rewrite, `stopAllPoolCopies` on fencing.
- `src/courtesy.ts`: courteous mode. `courtesyRound` (called by `scaleTick`, at most once a minute): asks the helpers for their owner's CPU, `courtesyObserve` (pure: 2 readings at or above the limit → busy, 5 min below 80% → free; streaks in `pool/courtesy.json`), marks `ownerBusy` under the state lock and reconciles (mode `auto`: like a pause; `warn`: copies stay). `courtesyOf` / `ownerBusy` / `ownerWantsOut` / `setCourtesy` live in pool.ts.
- `src/wol.ts`: Wake-on-LAN, low level (no pool import): `magicPacket`, `broadcastFor`, `validateBroadcast` (private networks or 255.255.255.255 only), `originAddressFor` (this server must be on the PC's network), `wakeOf` (settings re-checked), `sendMagicPacket` (offline: recorded in `offlineSent`), tries in `pool/wake.json` (`wakeStatus` pure: idle/waking/retry/gave_up, 3 tries `PAASMCP_WAKE_WAIT_SECONDS` apart), `wakeHelper`, `noteWakeAnswers`. Callers: `reconcilePool` (`wakeForRoom` when no awake PC fits; a kept copy on a PC not answering), `applyStep` (`held: "waking"`, retried after `PAASMCP_WAKE_RECHECK_SECONDS` by `holdStep`), `probeHelpers` (`recordWakeAnswers` → diary `woke`).
- `src/wake.ts`: Wake-on-LAN, pool side: `wakeRound` (called by `scaleTick` after the courteous check: asks only PCs being woken, retries, gives up with diary `wake_failed`, reconciles apps once a woken PC answers, under the state lock) and `setWake` (`pool wake <name> on|off|now`, free, audited `pool.wake`).
- `src/poolproto.ts`: pure protocol shared by both sides: invite text, `parseOrder` (fixed order names, argument patterns), `keyLine` (`from=`, `command=`, `restrict`), `buildRunArgs`, `renderEnvFile`, image fingerprint, validators for everything a helper answers, `ownerShare` (the owner's CPU share between two counter snapshots) and the cgroup / `/proc/stat` parsers.
- `src/worker.ts`: runs on the helper as the SSH forced command, one order per session, then exits (nothing resident). Writes variables only to tmpfs (`checkSecretsDir`), never `--env`. `facts`/`list` add the owner's CPU reading (`ownerReading`, last snapshot in `owner.json`) and the card of the default route (`lanFacts`, for Wake-on-LAN); `load`/`run` mark the window as Docker's.
- `src/pooljoin.ts`: helper-side `pool join` / `leave` / `update-worker` / `wake-setup` (root): user `paasmcp-worker`, root-owned worker copy in `/usr/local/lib/paasmcp-worker`, one `authorized_keys` line, tmpfiles.d entry, self test; `setupWake` arms the wired card (`ethtool -s <if> wol g`, oneshot unit `paasmcp-wol.service`, NetworkManager, marker `/etc/paasmcp-wol.json`), `undoWakeSetup`.
- `src/dashboard.ts`: Modern Web Workspace Control Plane (`127.0.0.1:4099`) with CSP/security headers, login rate-limiting, XSS escaping, PT-BR/EN i18n, Dark/Light themes, and Webhook/Federation HTTP endpoints.
- `src/resources.ts`: server resources for the dashboard's Resource usage card: whole-server CPU (`os.cpus()` samples around the `docker stats` call), memory (`MemAvailable`) and disk (`statfs` of `PAASMCP_ROOT`), split into PaaSMCP (`paasmcp-*` containers) and others. Host-correct inside the dashboard container. `resourceSnapshot` (mcp-server.ts) runs `docker stats` once for both this and `getContainerMetrics`.
- `src/usage.ts`: background round every 10 min in the dashboard (`startUsageLoop`): disk split (du + `docker system df -v`) to `usage/latest.json`, database sizes (pg_database_size, Redis keys via stdin AUTH), hourly `usage/db-history.ndjson` (90 days), and the optional per-database warning size (`warnSizeMb`, notices at 80%/100%, never blocks). `setDatabaseLimit` expects the caller to hold the state lock (dashboard POSTs already do).
- `src/mcp-server.ts`: `createMcpServer(level)` with all 23 `paas_*` tools (stdio entry point runs with full level).
- `src/mcp-http.ts`: Stateless Streamable HTTP endpoint `/mcp` (bearer token, loopback/Tailscale only).
- `src/tokens.ts`: Personal MCP tokens (hashed, levels read/deploy/destroy).
- `src/totp.ts`: RFC 6238 TOTP for the dashboard second factor.
- `src/cli.ts`: Command-line interface (`paasmcp`).
- `src/test.ts`: Node.js native security & unit test runner suite (`node --test`).

## Rules for Agents Modifying PaaSMCP
1. **Never hardcode personal domains, Cloudflare IDs, email addresses, or proprietary names** in `src/` or `docs/`. All server-specific configuration must live in `/opt/homelab/paasmcp/state.json` or encrypted `.enc.json` files.
2. **Enforce strict security boundaries:**
   - Never pass unsanitized strings to a shell; always use `execFileSync` with argument arrays.
   - Always use `timingSafeCompare` when comparing tokens or HMAC signatures.
   - Never bind application or database ports to `0.0.0.0` on the host (`127.0.0.1` only). The only other address allowed is this machine's own Tailscale IP (`tailnetBindIp`), for the mirror, active-active and the helper pool.
   - Helper PCs are reached only through `sshOrder` (forced command, fixed orders). Never send app variables as `--env`/`--env-file` or write them to a helper's disk; they go in the `run` spec on stdin to the tmpfs file.
   - Never return plaintext secret values from MCP tools or API endpoints.
   - Every risky action goes through `src/guard.ts`: classify it in `assessRisk`, call `authorizeAgent` from MCP tools and `authorizeHuman` from the dashboard/CLI. Agents must never be able to approve their own requests.
   - Prefer "allow with warning + confirmation" over removing a feature; forbid only what has no safe use.
3. **Always run `npm run build && npm test`** after modifying any TypeScript file in `src/`.
